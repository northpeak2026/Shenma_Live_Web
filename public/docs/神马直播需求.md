# 有料

## 1. 有料模块概述

### 1.1 有料模块定位

有料模块用于展示体育赛事相关的专家推荐方案，支持用户浏览方案、查看专家战绩、购买收费方案、解锁推荐内容及查看结算结果。

有料模块需要与赛事、直播及用户个人主页打通，确保用户可以从不同业务入口查看同一份有料方案。

### 1.2 全局导航

在 Web Header 导航栏中新增【有料】入口，位置在【赛事】之后。点击后进入有料首页。

### 1.3 核心页面

1. 有料首页。
2. 专家排行榜。
3. 有料详情页。
4. 专家个人主页中的有料内容。
5. 赛事详情页中的有料 Tab。
6. 直播详情页中的有料 Tab。

## 2. 有料首页

### 2.1 页面布局

有料首页采用左右双栏布局。左侧为主要内容区域，展示有料列表。右侧为辅助信息区域，从上到下依次展示专家排行榜、焦点赛事。

建议初始布局比例：左侧约占内容区域的 70%，右侧约占 30%。具体比例可根据实际页面宽度调整。

### 2.2 左侧：有料列表

有料列表应当直接出现在页面顶部。用户进入有料首页后，第一屏就应当能够看到有料方案，而不是先浏览大面积的排行榜或焦点赛事。

列表支持以下筛选条件：

| 筛选条件 | 选项 | 规则 |
| --- | --- | --- |
| 赛事分类 | 足球、篮球 | 根据赛事类型展示适用的盘口 |
| 盘口分类 | 胜平负、胜负、让球、大小球 | 胜平负适用于足球，胜负适用于篮球 |
| 付费类型 | 全部、钻石、金币、免费 | 可与赛事、盘口分类组合 |

筛选条件可以采用横向 Tab、下拉选择器等适合 Web 的交互方式。筛选条件之间应当可以组合使用。

#### 有料卡片字段

每张卡片至少展示：

- 专家头像。
- 专家昵称。
- 专家胜率。
- 专家近期战绩，例如近 10 场中 9 场。
- 专家当前连红次数。
- 有料标题。
- 关联赛事信息。
- 盘口类型。
- 盘口数值。
- 赔率。
- 发布时间。
- 收费方式。
- 收费价格。
- 已结算方案的结果标识。

卡片采用适合左侧内容宽度的多列布局，具体列数根据实际空间调整。需要优先保证专家信息、赛事信息、盘口、价格和结算状态清晰可见。

> 关键限制：未购买的收费方案不得在卡片中暴露实际推荐方向。

| 点击对象 | 跳转目标 |
| --- | --- |
| 有料卡片 | 对应有料详情页 |
| 专家头像或昵称 | 专家个人主页，默认选中【有料】Tab |

### 2.3 右侧：专家排行榜

右侧展示胜率榜、回报榜、连红榜。由于右侧空间有限，三个排行榜采用 Tab 切换，而不是三个榜单横向排列。默认展示胜率榜。

每个榜单展示前 9 名专家，第 10 个位置作为【更多】入口。

排行榜字段包括：排名、专家头像、专家昵称、对应榜单指标。前三名可以通过排名颜色或图标适度突出。

点击专家头像或昵称进入专家个人主页。点击【更多】进入对应榜单详情页，展示前 30 名专家。

#### 排行榜统计规则

统一使用最近 7 天的数据。

| 榜单 | 统计条件 | 排序指标 |
| --- | --- | --- |
| 胜率榜 | 最近 7 天发布的方案数量大于 5，胜率大于 55% | 胜率 |
| 回报榜 | 最近 7 天发布的方案数量大于 5，回报率大于 100% | 回报率 |
| 连红榜 | 最近 7 天发布的方案数量大于 5，连红次数大于 2 | 连红次数 |

不同榜单应使用对应的指标排序。排行榜的统计口径应保持一致，不能因为入口不同而使用不同的数据规则。

### 2.4 右侧：焦点赛事

焦点赛事展示在专家排行榜下方。只展示同时满足以下条件的赛事：

1. 被后台标记为热门赛事。
2. 该赛事关联了有料方案。
3. 赛事状态为未开赛或进行中。

赛事卡片展示：

- 联赛名称。
- 开赛时间或比赛进行时间。
- 主队 Logo。
- 主队名称。
- 客队 Logo。
- 客队名称。
- 关联的有料方案数量。

右侧空间有限，赛事卡片应采用紧凑布局。

点击赛事卡片后，进入该赛事对应的有料列表。该列表只能展示当前赛事关联的有料方案。

> 关键限制：不得跳转到普通赛事详情页后再要求用户手动查找有料内容。

### 2.5 首页布局验收要求

- 有料列表位于页面主要内容区域。
- 专家排行榜与焦点赛事位于右侧。
- 首屏可以看到多条有料方案。
- 排行榜可以切换三个榜单。
- 焦点赛事可以正常进入对应赛事的有料列表。
- 所有筛选条件均可正常使用。
- 不因为右侧信息较多而挤压左侧列表。

## 3. 有料详情页

### 3.1 页面布局

采用适合 Web 的左右双栏结构。

| 区域 | 展示内容 |
| --- | --- |
| 左侧有料主体 | 赛事信息、盘口信息、专家推荐方向、有料正文、结算结果 |
| 右侧辅助信息 | 专家资料、专家近期战绩、购买信息、其他相关信息 |

具体布局可以根据当前项目的组件体系调整，但不能直接使用移动端底部固定购买栏的布局。

### 3.2 专家信息

展示专家头像、专家昵称、胜率、近期战绩、连红次数。

点击专家信息进入专家个人主页，默认选中【有料】Tab。

### 3.3 有料基础信息

展示有料标题、发布时间、关联赛事、盘口类型、盘口数值、赔率。

### 3.4 专家推荐方向

#### 未购买的收费方案

- 展示该盘口的全部选项。
- 展示对应数值及赔率。
- 不高亮任何推荐选项。
- 不得通过颜色、样式、文案、排序或其他数据提前暴露推荐方向。

#### 已购买的收费方案

- 明确高亮专家实际推荐的盘口选项。
- 用户应当能够快速识别推荐方向。

#### 免费方案

- 无需购买。
- 直接展示推荐方向和完整正文。

### 3.5 有料正文

#### 未购买的收费方案

- 正文区域使用毛玻璃或模糊遮罩效果。
- 展示解锁提示。
- 展示购买截止倒计时。
- 不得通过遮罩之外的其他信息泄露推荐正文。

#### 已购买的收费方案

- 移除正文遮罩。
- 展示完整正文。
- 同步高亮专家推荐方向。

#### 免费方案

直接展示完整正文。

### 3.6 购买区域

展示当前方案价格、支付资产类型、用户对应资产余额、立即支付按钮。支持的支付资产为金币、钻石。

支付规则：

1. 根据方案配置使用对应资产。
2. 余额不足时，明确提示用户。
3. 购买成功后更新用户资产余额。
4. 购买成功后立即解锁方案，无需刷新页面。
5. 购买成功后同步更新该方案的购买状态。
6. 已购买方案不可重复支付。
7. 用户在其他入口打开同一方案时，应当继续保持已解锁状态。

### 3.7 购买截止时间

| 状态 | 展示与行为 |
| --- | --- |
| 尚未截止 | 展示剩余购买时间，倒计时正常更新 |
| 已截止 | 停止倒计时，展示【已截止】状态，未购买用户不可继续购买；已购买用户仍可以正常查看完整内容 |

> 关键限制：购买截止时间必须由统一的方案状态决定，不能在不同页面分别计算出不同的截止状态。

## 4. 有料结算结果

### 4.1 结算状态

支持以下五种结算结果：

| 结果 | 展示要求 |
| --- | --- |
| 赢 | 明确展示成功状态 |
| 赢半 | 明确展示部分获胜状态 |
| 走水 | 使用独立的中性状态 |
| 输半 | 明确展示部分失利状态 |
| 输 | 明确展示失败状态 |

不能将所有结果简单归纳为成功和失败两种状态。

### 4.2 列表展示

已结算方案在有料列表卡片中展示对应的结算结果标签。

### 4.3 详情页展示

详情页需要明确体现：

- 专家实际推荐的方向。
- 该推荐方向对应的最终结算结果。

对于已购买或免费的方案，可以正常展示推荐方向及结算状态。

### 4.4 未购买的收费方案

即使方案已经结算，未购买用户也不能直接看到实际推荐方向。结算结果的展示不得绕过付费内容保护规则。

## 5. 专家个人主页与主播个人主页融合

### 5.1 基本原则

Web 项目已经存在主播个人主页。本次不单独开发一套完全独立的专家个人主页，而是将主播和有料专家的个人主页进行融合。同一个用户可能同时具有主播身份和专家身份。

### 5.2 身份展示规则

| 用户身份 | 个人主页展示 |
| --- | --- |
| 仅主播 | 展示直播相关内容 |
| 仅专家 | 展示有料相关内容 |
| 同时是主播和专家 | 同时展示直播和有料两个 Tab |

### 5.3 直播 Tab

保留原有主播个人主页功能，包括：

- 直播预告。
- 直播回放。
- 原有主播相关信息。

不得因为增加专家身份而破坏现有主播个人主页。

### 5.4 有料 Tab

展示：

- 专家战绩数据。
- 胜率。
- 回报率。
- 连红次数。
- 专家发布的有料方案列表。

点击方案进入对应有料详情页。

### 5.5 入口联动

| 入口 | 默认选中 |
| --- | --- |
| 从直播模块点击主播头像进入个人主页 | 【直播】Tab |
| 从有料模块点击专家头像进入个人主页 | 【有料】Tab |

用户可以在个人主页中自由切换两个 Tab。同一个用户的直播与有料内容应使用统一的用户身份，避免出现两套互不关联的个人主页。

## 6. 赛事详情页新增有料 Tab

### 6.1 Tab 位置

在赛事详情页现有【阵容】Tab 后新增【有料】Tab。保留其他现有 Tab 和功能，不调整其他 Tab 的顺序。

### 6.2 数据展示

点击【有料】Tab 后，展示当前赛事关联的全部有料方案。

方案卡片复用有料模块的业务逻辑，展示：

- 专家头像、昵称。
- 专家战绩。
- 有料标题。
- 盘口信息。
- 收费方式与价格。
- 购买状态。
- 结算状态与结果。

### 6.3 赛事关联规则

1. 根据当前赛事 ID 查询关联方案。
2. 不能使用联赛 ID 代替赛事 ID。
3. 只能展示当前赛事的有料方案。
4. 同一赛事可以关联多个专家的多条方案。
5. 不得展示其他赛事的有料数据。

### 6.4 页面跳转

| 点击对象 | 跳转与行为 |
| --- | --- |
| 有料卡片 | 进入对应有料详情页，保留原有购买、解锁、截止时间和结算逻辑 |
| 专家头像或昵称 | 进入对应专家个人主页，默认选中【有料】Tab |

### 6.5 空状态

即使当前赛事没有关联有料，也保留【有料】Tab。展示合适的空状态，例如：【暂无相关有料】。

> 关键限制：不得使用其他赛事的方案填充。

### 6.6 布局要求

- 复用赛事详情页现有的 Tab 容器。
- 根据当前内容区域宽度调整有料卡片。
- 不直接套用有料首页的左右双栏布局。
- 不影响技术统计、赛况、阵容等其他模块。

## 7. 直播详情页新增有料 Tab

### 7.1 Tab 位置

在直播详情页现有【赛况】Tab 后新增【有料】Tab。不影响其他现有 Tab 的功能与顺序。

### 7.2 Tab 展示条件

直播间的有料数据来源于当前直播绑定的赛事。只有同时满足以下条件时，才展示【有料】Tab：

1. 当前直播绑定了赛事。
2. 该赛事存在关联的有料方案。

如果直播没有绑定赛事，或者绑定的赛事没有关联有料方案，则不展示【有料】Tab。其他 Tab 正常展示。

### 7.3 数据展示

点击【有料】Tab 后，展示当前绑定赛事关联的全部有料方案。可以包含其他专家发布的方案，不限于当前主播发布的方案。

方案数据应与以下页面保持一致：

- 有料首页。
- 赛事详情页。
- 有料详情页。
- 专家个人主页。

### 7.4 页面跳转

| 点击对象 | 跳转目标 |
| --- | --- |
| 有料卡片 | 对应有料详情页 |
| 专家头像或昵称 | 专家个人主页，默认选中【有料】Tab |

### 7.5 布局要求

直播详情页的内容区域宽度有限，应采用适合当前容器的紧凑布局。建议使用单列紧凑卡片。

重点保证以下信息清晰可见：

- 专家信息。
- 赛事信息。
- 盘口信息。
- 收费价格。
- 购买状态。
- 结算结果。

不能直接使用有料首页的大尺寸卡片布局。
